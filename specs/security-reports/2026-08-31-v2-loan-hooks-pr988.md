## Verdict

**PASS** — No P0 or P1 findings. Two P2s deserve action before merge (Aave trust-boundary documentation/allowlist requirement; fork-verification of the Aave V4 Spoke behavioral claims); the third P2 is a trivially hoistable code-duplication fix.

### Verified-safe highlights (explicitly probed)

- **Morpho full repay is share-denominated** (`repay(0, borrowShares)` after `accrueInterest`) — immune to the knife-edge accrual DoS that hit the sibling Euler review; `MorphoBalancesLib` accrual math verified against Morpho core (`wTaylorCompounded` + `toAssetsUp`).
- **Aave V3/V4 sentinels pass `type(uint256).max` natively**; per-timestamp index accrual means snapshot→settle within one transaction cannot drift; `MAX_WITH_PREV_NOT_ALLOWED` enforced on every sentinel path.
- **Morpho callbacks disabled** — every `supplyCollateral`/`repay` passes empty `data`, so no `onMorpho*` callback surface exists.
- **Approval hygiene:** approve-0 / approve-exact / op / approve-0 on every leg of every branch, including after `repay(max)`; malicious-IRM rate divergence analyzed — no path leaves a dangling allowance.
- **`onBehalfOf`/receiver hardcoded to `account`** in every provider call; no credit delegation, no `repayWithATokens`, no V4 position-manager grants, no Morpho `setAuthorization` — no standing authority is ever created.
- **`inspect()` completeness:** Morpho exposes singleton+tokens+oracle+irm+lltv; Aave V3 pool+tokens+rateMode; Aave V4 spoke+tokens+both reserveIds — every trust-sensitive address reachable by off-chain allowlisting.
- **Fail-closed transients:** all four settle transients are consumed via strict equality (`DELTA_MISMATCH`) or direction checks; no boolean flag whose poisoning skips a check (residual ERC-777 interleaving caveat is P3-4).
- **Encoding strictness:** exact lengths (230/178/241), canonical bools, reserved-zero enforcement, `IDENTICAL_TOKENS`, rate-mode pinned to 2; ERC-165 loans advertisement is honest for all nine hooks (all three layouts carry real token fields at the fixed offsets — no reserved-zero collateral slot issue here).
- **Executor determinism:** `_processHook` runs build after the previous hook's postExecute; `validateHookCompliance` bans mid-batch calls to the hook itself; per-occurrence execution-context nonces make repeated hook use in one chain safe.

## P2 Findings (Medium)

### [P2-1] Aave V3 `pool` / Aave V4 `spoke` come from user calldata with only a zero-address check — off-chain leaf allowlisting is the sole barrier

- **File:** `src/hooks/loan/aave-v3/BaseAaveV3LoanHookV2.sol:139`, `src/hooks/loan/aave-v4/BaseAaveV4LoanHookV2.sol:144, 162-170`
- **Category:** Access Control / Logic
- **Description:** `BaseMorphoLoanHookV2` pins the Morpho singleton as a constructor immutable; the Aave hooks decode `pool`/`spoke` from calldata at offset 92 with only nonzero validation. Aave V4's `_validateReserves` is circular — it asks the calldata-supplied spoke about itself, so a malicious spoke passes trivially. The settle checks bound wallet-token movement to the signed amounts but do not verify a genuine lending position was created.
- **Exploit Scenario:** A leaf with a malicious `pool` gets signed (phishing frontend, compromised leaf-builder, allowlist gap). The fake pool pulls `amount1` collateral and returns `amount2` loan tokens — both deltas pass — but no real position exists: the user permanently loses the overcollateralization margin (typically 20–60% of collateral value). Blast radius is bounded (approvals reset in-tx, `onBehalfOf`/`to` hardcoded, no standing authority) — hence P2, not P1.
- **Related (Morpho variant):** the Morpho singleton is pinned, but Morpho market creation is permissionless — a hostile market pairing *real* tokens with an attacker oracle/IRM on the genuine singleton passes any token-only allowlist. Real-world precedent: PAXG/USDC oracle-decimals exploit (Oct 2024, ~$230K); Stream Finance xUSD hardcoded-$1-oracle markets (Nov 2025, ~$93M+ bad debt). `inspect()` exposes oracle+irm+lltv precisely so vetting can catch this.
- **Secure Pattern:** Pin the pool via constructor immutable (Morpho/Euler precedent) or validate against the canonical `PoolAddressesProvider`/registry. If calldata-sourcing is retained for multi-market deployment, the requirement is off-chain and must be documented as such in SECURITY.md: leaf vetting MUST hard-allowlist `pool`/`spoke`, and for Morpho MUST validate the **full** `MarketParams` tuple (oracle, IRM, lltv — not just token addresses).
- **Reference:** vulnerabilities.md Sections 8.2, 14.3; Verichains PAXG analysis; Morpho risk docs

### [P2-2] Hand-written `IAaveV4Spoke` encodes unverified behavioral claims about a brand-new protocol; zero-tolerance delta checks amplify any divergence into a deterministic DoS

- **File:** `src/vendor/aave-v4/IAaveV4Spoke.sol:44-45, 62-64, 72-75` (consumed by all three V4 hooks)
- **Category:** Token / Logic (integration assumption)
- **Description:** The interface asserts: `repay(max)` pulls exactly `drawnDebt + premiumDebt` per `getUserDebt` at the same timestamp; `withdraw(max)` transfers exactly `getUserSuppliedAssets`; `setUsingAsCollateral` is idempotent; `supply`/`borrow` move exactly `amount`. Aave V4 (launched on mainnet ~2025, hub-and-spoke, share-based ledger accounting — every function returns `(shares, assets)`) is new and still evolving. With strict `DELTA_MISMATCH` equality there is zero tolerance: a ±1 wei divergence between the Spoke's internal rounding and its view getters makes every sentinel-based V4 leaf deterministically revert (no fund loss — liveness). If the idempotency claim is wrong, the open hook is unusable for accounts that already enabled the collateral reserve. Note Aave v3.5 changed aToken burn rounding **up** — rounding behavior in the Aave stack is actively moving.
- **Secure Pattern:** Fork-test each claim against the deployed Spoke bytecode before mainnet deployment (exact-pull on `repay(max)` with nonzero premium debt; `withdraw(max)` exactness; `setUsingAsCollateral` idempotency; supply/borrow exactness), and gate V4 hook deployment on those tests in CI.
- **Reference:** vulnerabilities.md Sections 8.4, 22.3; Aave v3.5 StErMi audit; Aave V4 docs

### [P2-3] `_resolveRepayLeg` duplicated verbatim between each family's Repay and RepayAndWithdraw hooks (3 copies × ~23 lines)

- **File:** `MorphoRepayHookV2.sol:107` / `MorphoRepayAndWithdrawHookV2.sol:140`; `AaveV3RepayHookV2.sol:96` / `AaveV3RepayAndWithdrawHookV2.sol:130`; `AaveV4RepayHookV2.sol:100` / `AaveV4RepayAndWithdrawHookV2.sol:137`
- **Category:** Logic (maintainability → drift risk)
- **Description:** In all three families the repay-leg resolver is copy-pasted between the standalone and composite hooks — the duplication is even self-acknowledged in NatSpec ("identical semantics to X"). Sentinel/`usePrevHookAmount` semantics are safety-critical; a fix applied to one copy but not its sibling silently forks behavior between hooks that promise identical semantics. Each copy is hoistable into the family base with zero signature changes.
- **Secure Pattern:** Move `_resolveRepayLeg` once into `BaseMorphoLoanHookV2` / `BaseAaveV3LoanHookV2` / `BaseAaveV4LoanHookV2`; delete the six leaf copies. (Same treatment the sibling Euler review applied via `_resolveCloseLegs`.)
- **Reference:** coding-rules.md (reusability); vulnerabilities.md Section 36

## P3 Findings (Low — security)

### [P3-1] Dust-debt griefing on exact-amount repay legs (+ inaccurate NatSpec about the sentinel path)
- **File:** `MorphoRepayHookV2.sol:36-38` and all repay hooks. Morpho repay and Aave repay-on-behalf are permissionless: a third party shrinking the victim's debt below a signed exact `repayAmount` cancels the whole intent (Morpho share underflow / Aave `DELTA_MISMATCH`). The `max` sentinel path is robust (resolves live) — only a *complete* third-party repayment triggers `NO_OUTSTANDING_DEBT` there, so the NatSpec claim that full repayment "can be front-run by repaying 1 wei" is inaccurate for V2 and should be corrected. Builders should emit the sentinel for close intents. (Cross-ref: the Euler hooks resolved the donation case gracefully — `_resolveRepayCap` returns `(0, clear)`; consider the same pattern here in a follow-up.)

### [P3-2] `_settleRepay` publishes spent tokens through the producer pipe
- **File:** `BaseLoanHookV2.sol:193-199`. `outAmount = loanSpent` / `outToken = loanToken` passes all pipe validation, so a builder bug chaining `usePrevHookAmount` after a standalone repay silently spends an equal amount of *unrelated* wallet balance instead of failing. Publish `outAmount = 0` for terminal repay hooks, or reject `usePrevHookAmount` legs whose predecessor subtype is `LOAN_REPAY` in off-chain validation.

### [P3-3] Aave V3 open hook relies on supply's collateral auto-enable
- **File:** `AaveV3SupplyAndBorrowHookV2.sol:62-83`. V3 does **not** auto-enable when the asset is isolation-mode-constrained or was previously disabled with a nonzero aToken balance — the borrow leg then reverts (fail-closed dead leaf). The V4 hook already calls `setUsingAsCollateral` explicitly; mirror that with `setUserUseReserveAsCollateral(collateralToken, true)` after supply. Related reserve-state gates (caps, pause/freeze, siloed borrowing) should be pre-checked during off-chain vetting.

### [P3-4] Plain (non-context-keyed) settle transients — ERC-777 interleaving fails open, not closed
- **File:** `BaseLoanHookV2.sol:38-58`. A callback-bearing token inside the victim's own signed chain could re-run `preExecute` for a different account mid-settle and re-snapshot values such that the victim's `_settle*` *passes* where it should have failed (the documented caveat understates this direction). Context-key the four transients with BaseHook's `_makeKey(context, offset)` machinery (requires exposing it or replicating the pattern). Trust boundary matches SECURITY.md's callback-token exclusion — hence P3.

### [P3-5] External view decoders panic on short data
- **File:** `BaseLoanHookV2.sol:103-118`, family bases, `BaseLoanHook.sol:76-95`. `decodeUsePrevHookAmount`, `decodeAmounts`, `replaceCalldataAmounts` and the token getters index without length checks — Panic(0x32)/BytesLib require-string instead of `INVALID_DATA_LENGTH`. Execution paths are safe (strict decoders check first). Also: standalone-repay `decodeAmounts` returns the raw `max` sentinel as an IN amount — off-chain sizing consumers must special-case it.

### [P3-6] `_resolvePrevHookOutput` hard-fails on outToken-less legacy predecessors
- **File:** `BaseLoanHookV2.sol:134-147`. Legacy hooks that set only `outAmount` return `getOutToken == address(0)` → `PREV_TOKEN_MISMATCH` at execution. Fail-closed and arguably intended, but it is a silent behavioral delta vs V1 chaining — enumerate which deployed hooks set `outToken` and gate leaf-building; note in the migration doc.

## Attack Surface Summary

- **External Entry Points:** hook lifecycle (`build`/`preExecute`/`postExecute`, mutex/context-gated), pure/view decoders, `ISuperHookLoans` getters, `inspect()`.
- **Value Transfer Points:** ERC-20 approvals + `supply/supplyCollateral/borrow/repay/withdraw` on Morpho singleton (pinned) and calldata-supplied Aave pool/spoke (see P2-1); all receivers/debtors hardcoded to `account`.
- **Oracle Dependencies:** none direct; each Morpho market carries a calldata-identified oracle (in `inspect()`); Aave pools carry their own oracle stacks; a hostile market/pool oracle is the primary economic risk — controlled off-chain.
- **Trust boundary:** hook calldata is user-signed (Merkle leaf) and vetted off-chain via `inspect()`. For Aave, and for Morpho market params beyond the singleton, that vetting is the **sole** barrier — treat the vetting pipeline as security-critical infrastructure (precedent: Morpho's own Apr 2025 frontend/SDK approval-misroute incident, ~$2.6M exposed by an off-chain config error).
- **Upgrade Mechanisms:** none — hooks immutable; no standing authority created on any path.

## External research notes

- **Hostile Morpho markets:** PAXG/USDC oracle-decimals exploit (Oct 2024); Stream Finance xUSD $1-oracle markets (Nov 2025). Vet the full MarketParams tuple.
- **Per-protocol full-debt divergence** (Morpho by shares / Aave by max) — correctly implemented in this PR (verified).
- **Aave V3 reserve gates** (isolation, e-mode, siloed, caps, pause/freeze) — liveness constraints for the open hook (P3-3); atomicity of the supply+borrow batch verified.
- **Aave V4 is architecturally new** (hub-and-spoke, ledger positions, reserveId-keyed, position-manager auth): audited by Sherlock/Blackthorn + public contest with no crit/high findings, but integrator-facing behavior is the risk (P2-2). The hooks correctly avoid the position-manager surface entirely.
- **Router/approval drains 2024-25** (Socket $3.3M, LI.FI ~$10M): neutralized here by exact-amount approve + same-batch reset + no attacker-reachable call-target selection (verified).

## Coding Standards Findings

1 P2 (the `_resolveRepayLeg` triplication, promoted to P2-3 above) and 11 P3 polish items from the standards agent:

1. Internal-helper NatSpec inconsistently tagged (`_settle*`, `_balance*`, `_resolve*Leg` lack `@param`/`@return` while the strict decoders are fully tagged) — worst for `_resolveRepayLeg`'s three-value return.
2. Same-concept constants named three ways (`AMOUNT_POSITION` vs `AMOUNT1_OFFSET`; `USE_PREV_HOOK_AMOUNT_POSITION` vs `USE_PREV_OFFSET`) — alias in the Morpho base and unify.
3. Redundant calldata word re-read in all three strict decoders (`_requireZeroWord` re-reads the already-decoded `amount2`).
4. `MorphoRepayHookV2._preExecute` builds `MarketParams` twice and the full-repay branch fetches `position()` twice (once in `_borrowShares`, again inside `expectedBorrowAssets`) — materialize once / add a shares-accepting overload.
5. Missing CONSTRUCTOR banners in the three Aave V3 leaves (Morpho + V4 leaves have them).
6. `decodeUsePrevHookAmount` override sits under `EXTERNAL METHODS` in the Morpho base but `SIZING-INTERFACE PLUMBING` in both Aave bases — normalize.
7. Unused `Id` import in `BaseMorphoLoanHookV2`.
8. Duplicate immutables `morpho` / `morphoStaticTyping` holding the same address — cast at call sites instead.
9. Dead zero-check in `MorphoRepayAndWithdrawHookV2._resolveWithdrawLeg` (subsumed by the post-resolution check) — or restructure to the Aave early-return shape.
10. `_resolveOpenAmounts` triplicated across families (identical logic; hoistable to `BaseLoanHookV2` as a scalar helper).
11. Field-decode ordering differs in `_decodeAaveV4V2` vs siblings (cosmetic).

Compliant areas: fixed pragma 0.8.30 in all hook files (vendor Morpho libs float `^0.8.0` consistently with existing vendored libs — not flagged); custom errors only, fully NatSpec'd; import organization; naming; visibility/mutability; approve bracketing explicitly commented; documented trade-offs (fee-on-transfer exclusion, front-run limitation, transient-storage caveat); `IAaveV4Spoke`/`MorphoBalancesLib` are the best-documented files in the set; clean build, zero warnings.

## Fixes Applied (2026-08-31)

- **P2-1 (accepted — not fixed):** pinning the Aave V3 `pool` / V4 `spoke` as immutables would force
  a separate hook deployment per market/chain, which is not acceptable. The calldata-sourced design
  stays; the control is off-chain leaf allowlisting of `pool`/`spoke` (and, for Morpho, the full
  `MarketParams` tuple incl. oracle/IRM/lltv), which `inspect()` fully exposes. Documented as the
  security-critical trust boundary.
- **P2-2 (fixed):** the Aave V4 fork suite already exercised the load-bearing Spoke claims against
  the real Spoke at the pinned block — supply/borrow exact amounts (`Open_Exact`), `repay(max)`
  exact-pull with accrued/premium debt and `withdraw(max)` exactness (`Close_Full_AfterWarp`,
  `Repay_FullViaMax`). Added `test_AaveV4V2_Open_SecondOnSameReserve_CollateralAlreadyEnabled` to
  close the one gap: it opens twice on the same reserve, proving `setUsingAsCollateral(true)` is a
  real no-op when already enabled (a revert there would have bricked every second position).
- **P2-3 (fixed):** `_resolveRepayLeg` hoisted into each family base
  (`BaseMorphoLoanHookV2` / `BaseAaveV3LoanHookV2` / `BaseAaveV4LoanHookV2`); the six leaf copies
  deleted. `_resolveOpenAmounts` (finding #11) hoisted into `BaseLoanHookV2._resolveOpenAmount1`
  and the three leaf copies deleted. Safety-critical sentinel/`usePrevHookAmount` logic now lives in
  exactly one place per concept.
- **P3-1 (fixed):** corrected the inaccurate front-run NatSpec on both Morpho repay hooks — the
  sentinel path resolves debt live and is robust to partial third-party repays; only a *complete*
  donation trips `NO_OUTSTANDING_DEBT`, and only an exact non-sentinel amount is 1-wei griefable.
- **P3-2 (fixed):** `BaseLoanHookV2._settleRepay` now publishes `outAmount = 0` (keeping `outToken`
  for classification). A terminal repay produces nothing; publishing the spend let a downstream
  `usePrevHookAmount` consumer double-spend unrelated balance — zero makes any such chaining fail
  closed (the prev-hook pipe rejects a zero amount).
- **P3-3 (fixed):** the Aave V3 open hook now emits an explicit
  `setUserUseReserveAsCollateral(collateralToken, true)` after supply (added to the vendor `IPool`),
  mirroring the V4 hook — covers the isolation-mode / previously-disabled-reserve cases where supply
  does not auto-enable. Verified against the real Aave V3 pool by the E2E fork suite.
- **P3-4 (skipped — documented):** context-keying the four settle transients would require the
  audited pre-existing `BaseHook` key machinery, and transient mappings do not compile on 0.8.30
  (`Transient data location is only supported for value types`). The fail-open interleaving requires
  a callback-bearing token inside the victim's own signed chain — already a documented SECURITY.md
  exclusion. Kept with the honest NatSpec caveat.
- **P3-5 (fixed):** exact-length guards added to every new external view decoder
  (`decodeUsePrevHookAmount`, `decodeAmounts`, `replaceCalldataAmounts` in all three family bases) —
  custom `INVALID_DATA_LENGTH` instead of an out-of-bounds panic.
- **P3-6 (fixed):** documented the outToken-less-predecessor `PREV_TOKEN_MISMATCH` behavior in
  `_resolvePrevHookOutput` NatSpec.
- **Style #2/#3/#4/#6/#7/#12 (fixed):** `@param`/`@return` tags on the hoisted resolvers and the
  balance/withdraw helpers; constant aliases (`AMOUNT1_OFFSET`/`USE_PREV_OFFSET`) in the Morpho base
  so all three families read alike; redundant `_requireZeroWord` re-read replaced with a check of
  the already-decoded word in all three decoders; CONSTRUCTOR banners added to the three Aave V3
  leaves; Morpho's sizing banner renamed to match the Aave bases; Aave V4 decode order aligned to
  the siblings.
- **Style #5 (partial):** `MorphoRepayHookV2._preExecute` now materializes `MarketParams` once
  (matching its sibling); the deeper `expectedBorrowAssets`/`position()` double-read via a
  shares-accepting overload was left as-is (would touch `MorphoBalancesLib`).
- **Style #8 (fixed):** removed the unused `Id` import from `BaseMorphoLoanHookV2`. **#9 (skipped):**
  the duplicate `morphoStaticTyping` immutable matches the V1 base and removing a public getter is
  churn for near-zero benefit. **#10 (fixed):** the dead zero-check in Morpho `_resolveWithdrawLeg`
  restructured to the Aave early-return shape.
